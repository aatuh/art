# Earth rendering and asset contract

This is the implementation reference for **A World in Light**. It records what the static browser
build actually renders, how every runtime texture can be reproduced, and where the scientific
analogy ends.

## Runtime and failure boundary

The artwork is Rust compiled to WebAssembly and rendered with WebGL 2. It loads only committed,
same-origin files from the static site: NASA is contacted by explicit authoring commands, never by a
visitor's browser. Astronomical state stays in SI-unit `f64` coordinates on the CPU. Body positions
are made camera-relative in `f64` before the remaining metre values are narrowed to WebGL `f32`.
See [`planet-physics.md`](planet-physics.md) for the coordinate and navigation contract.

`tests/earth_assets.rs` rejects missing, truncated, placeholder-sized, or incorrectly dimensioned
assets. The browser independently checks decoded image dimensions before upload. A failed or
malformed image uses a bounded one-pixel fallback, allowing the installation to keep rendering in a
degraded state instead of accepting arbitrary texture dimensions or making a cross-origin request.
The raw terrain-height field has a compile-time byte-length contract and is uploaded directly from
the Wasm module as a single-channel texture.

## Reproduce the assets

Normal builds do not need Python or network access. Asset authoring needs Python 3, Pillow with
WebP support, NumPy, SciPy, and network access for the three pinned NASA fetches. From the repository
root, run:

```sh
python3 scripts/fetch-blue-marble.py
python3 scripts/generate-procedural-earth.py
python3 scripts/fetch-black-marble.py
python3 scripts/fetch-moon-albedo.py
cargo test --locked --test earth_assets
```

The fetchers accept no URL or output-path arguments. They use fixed HTTPS URLs, bounded downloads,
expected dimensions, and pinned SHA-256 values; Black Marble and LRO also require exact source byte
counts and reject unexpected redirects. Downloads are cached under ignored
`target/earth-authoring/`. The night-light and lunar output writers use same-directory temporary
files and atomic replacement; the five-output generator writes directly to `assets/earth/`, so it
should not run concurrently with a build.

`generate-procedural-earth.py` uses seed `0x45524154` by default. It converts the pinned Blue Marble
source into the 4096×2048 surface and derives the material, weather, diffuse-haze, and raw height
assets. The height field is computed after the material is quantized to RGBA8, so its texel centres
encode the same artistic land/elevation result that rendering and collision consume. Surface colour
is measured imagery; land classification is inferred from that colour, while relief, bathymetry,
material properties, clouds, polar additions, and sky haze are deterministic art direction rather
than measurements. Procedural longitude fields are generated by resampling the middle of a
horizontally tripled period and are rejected when their cyclic curvature is unlike the interior.
The weather map is encoded losslessly; runtime samplers repeat longitude and apply explicit,
distance-derived mip levels rather than branch-sensitive implicit derivatives.

### Blue Marble surface source

- Fixed source: [NASA June 2004 Blue Marble JPEG](https://assets.science.nasa.gov/content/dam/science/esd/eo/images/bmng/bmng-base/june/world.200406.3x5400x2700.jpg)
- Expected image: 5400×2700 JPEG, bounded to at most 3,000,000 downloaded bytes
- Source SHA-256: `dc059529b8ed1cfcdd59747a7c3f259c93c1322bf88ca1ec8bab1dd71fcc57f5`
- Dataset: [NASA Blue Marble Next Generation](https://science.nasa.gov/earth/earth-observatory/blue-marble-next-generation/)

NASA describes BMNG as a monthly, cloud-free 2004 global surface product assembled from MODIS
observations. Credit NASA Earth Observatory; the dataset page credits production by Reto Stöckli.
NASA also documents source limitations including noise over open water, simplified deep-ocean
colour/coastal blending, and possible snow/cloud confusion. Those limitations remain visible after
downsampling.

### Black Marble night-light source

- Fixed source: [NASA Black Marble 2016 JPEG](https://assets.science.nasa.gov/content/dam/science/esd/eo/images/imagerecords/144000/144898/BlackMarble_2016_01deg.jpg)
- Expected image: exactly 779,638 bytes, 3600×1800 JPEG
- Source SHA-256: `d87de751a264e4f8ff69c68de5dab9606daee87a6f15ae743c93200743bd7ec1`
- Dataset: [NASA Earth at Night maps](https://science.nasa.gov/earth/earth-observatory/earth-at-night/maps/) and [Black Marble 2016 credits](https://visibleearth.nasa.gov/images/144898/earth-at-night-black-marble-2016-color-maps/144957l)

The source is the 2016 0.1-degree grayscale global map derived from Suomi NPP VIIRS observations
selected for cloud-free nights. Credit NASA Earth Observatory imagery by Joshua Stevens, using
VIIRS data from Miguel Román at NASA Goddard Space Flight Center. The shader restricts this texture
to inferred land on the dark side; it is a static composite, not current electrical use or a live
Earth observation.

### SVS/LRO lunar source

- Fixed source: [NASA SVS `lroc_color_poles_2k.tif`](https://svs.gsfc.nasa.gov/vis/a000000/a004700/a004720/lroc_color_poles_2k.tif)
- Expected image: exactly 3,339,438 bytes, 2048×1024 TIFF
- Source SHA-256: `13b797422e8c4b8607ff2b2623ac3a046a6da0132d567c2d272d92fad7052c4a`
- Dataset: [NASA SVS CGI Moon Kit](https://svs.gsfc.nasa.gov/4720/)

The map is adapted from the Hapke-normalized Lunar Reconnaissance Orbiter Camera WAC mosaic of

## Multipass renderer

The WebGL adapter performs three bounded passes in this order:

1. A full-screen background shader clears to true black, adds the generated low-frequency galactic
   haze when ready, and draws a solar disc/corona whose angular scale follows the Sun's apparent
   radius.
2. A point pass draws exactly 1,800 fixed-seed, uniformly distributed star directions. Interleaved
   direction, linear colour, and CSS-pixel size data is generated in renderer-independent Rust;
   shader-side pixel scale is clamped from 0.5 to 2.0 before premultiplied-alpha blending. This is a
   synthetic visual catalogue, not a measured astrometric catalogue.
3. The orbital fragment program draws Earth and its 100 km atmosphere, Moon, and Sun only inside
   conservative scissor rectangles. Overlapping rectangles are merged, and fragments that hit
   neither a body nor atmosphere are discarded. Empty space therefore avoids the expensive
   atmosphere and cloud work.

Each pass currently produces display-ready colour independently. The background, point-star, and
orbital programs perform their own ACES-like tone mapping and sRGB conversion; there is no shared
HDR framebuffer with one scene-wide exposure/tone-map stage.

## Surface, light, atmosphere, and cloud model

- Earth starts from a WGS 84 oblate ellipsoid. Blue Marble supplies reference colour; the material
  texture supplies inferred land, normalized artistic elevation, roughness, and snow. A separate
  R8 field encodes 0–10,000 m of that final artistic height. WebGL and navigation bilinearly sample
  the same 2048×1024 texels with repeating longitude, clamped latitude, and WebGL texel-centre
  coordinates. For an ordinary ellipsoid hit, the shader applies four bounded distance corrections
  toward the displaced surface. Ill-conditioned limb hits and rays just above the reference horizon
  instead bracket the terrain inside its conservative shell and use up to sixteen bisections. The
  silhouette stays on the same full-resolution height field as foreground geometry and collision;
  its final coverage uses the signed closest-ray terrain clearance and
  a three-pixel physical metre span, including from a near-surface viewpoint. Limb pixels blend two
  complete paths: the terrain-hit path and a verified outward sky ray with its full cloud and
  atmosphere column. A fixed
  Earth-space local relief layer is bounded to 200 m and its amplitude fades smoothly from full
  detail at 100 km surface clearance to the base field alone at 300 km. Base-height mip selection
  instead follows a continuous screen footprint, so approaching the planet never changes the
  terrain field's coordinate frequency. Limb and ordinary-ray paths share this height function.
  CPU collision reserves the entire possible
  local envelope, so it is conservative rather than exactly equal to each rendered hill.
- Five additional Earth-fixed procedural bands filter smoothly from approach scale toward close
  material detail. They affect shading and colour without rescaling their coordinate domains as the
  camera moves. This texture-seeded procedural layer makes a global map more legible nearby; it
  does not infer real local geography.
- Every equirectangular image uses explicit distance-derived mip levels and repeat-wrapped
  longitude sampling. Shader code avoids implicit derivatives inside divergent body, land, and
  water branches. This prevents a coarse Pacific mip strip and removes driver-dependent
  close-surface aliasing; the longitude boundary is handled by repeat wrapping rather than an edge
  crossfade.
- Ocean waves are deterministic deep-water normal perturbations with gravity-based angular
  frequencies and five smoothly weighted wavelengths from about 33 km down to about 220 m. Every
  band is analytically attenuated when its phase would be smaller than a display pixel. Broad wave
  colour modulation fades out between 0.5 and 4 km of clearance so approach-scale swells cannot
  form screen-wide light/dark stripes. Two separately rotated, footprint-filtered noise bands add
  subtle non-directional water-surface variation without reintroducing moiré. Daylight
  water combines brighter depth-dependent albedo, Fresnel sky reflection, and a stronger
  Cox–Munk-inspired Beckmann solar glint (`alpha = 0.197`, `F0 = 0.0211`). There is still no fluid
  simulation, bathymetric wave propagation, breaking-wave model, planar reflection, or environment
  probe.
- Black Marble is reduced to a scalar light signal after subtracting coloured background chroma;
  only that sparse signal is tinted warm and applied to inferred land on the dark side. Snow
  attenuates the map; cloud occlusion and atmospheric transmission then affect the composite.
- The 100 km atmosphere uses six bounded view samples at every distance. Samples are quadratically
  concentrated toward whichever interval endpoint has denser air and transition smoothly to
  uniform spacing by 180 km of camera altitude;
  each one evaluates sunlight transmittance instead of tinting the entire path from one midpoint.
  The model uses Earth-scale Rayleigh (8 km) and Mie (1.2 km) density profiles, ozone extinction, a
  Mie asymmetry factor of 0.8, and eclipse visibility. A bounded blue-white daytime fill
  approximates missing multiple scattering near tangent views so a high-Sun horizon does not read
  uniformly as sunset. This remains an artistic single-scattering integration with a small
  multiple-scattering approximation, not a spectrally calibrated or global multiple-scattering
  model. Night ambient is nearly neutral, and restrained oxygen-green artistic airglow is limited
  to grazing limb rays rather than tinting the dark hemisphere.
- Clouds occupy terrain-relative volumes with a nominal 1.5 km above-ground base, ±350 m formation
  variation, and a 15 km top. The conservative trace shell includes maximum terrain height. The
  deterministic weather map includes broad storm
  tracks, an intertropical convergence band, dry subtropical regions, and a small fixed set of
  cyclonic systems. Most opaque clouds use a 1.5–4.2 km low profile, only strong systems grow toward
  12.5 km, and thin cirrus occupies roughly 6.5–15 km. The vertical split follows the broad ranges
  in the [WMO International Cloud Atlas](https://cloudatlas.wmo.int/en/clouds-definitions.html), not
  a simulated atmospheric state. Fixed Earth-space frequencies never rescale when camera distance
  changes. Each noise octave is attenuated against the ray's grazing-angle surface footprint before
  it becomes sub-pixel, and orbital and detailed density families blend smoothly from 1.2 Mm down
  to 0.3 Mm of surface clearance. Coherent endpoint branches avoid evaluating invisible field
  families. Views use exactly 12 deterministic, non-jittered volume samples with smoothly biased
  near-camera spacing; the traversed cloud interval is capped smoothly from 300 km on approach to
  60 km near the surface. Three-dimensional multi-octave density changes individual bases and tops,
  while deep systems form billowed towers rather than stacked image shells. A cheaper broad-density
  path supplies directional self-shadowing and surface shadows. The kilometre-scale surface-shadow
  lattice fades from 0.3 to 1.2 Mm of clearance and is skipped at orbital scale, where it would be
  unresolved and repeat as dark cells. Whole-Earth views retain broad volume modulation because
  real cloud depth is sub-pixel there. Rotated domains, quintic
  interpolation, and a two-lobe droplet phase approximation reduce grid motifs and approximate
  forward/back scattering.
  Extinction remains present at night. The weather and motion are
  deterministic art direction: there is no humidity, condensation, precipitation, conservation,
  fluid advection, or forecast meteorology. NASA's [cloud overview](https://www.nasa.gov/earth/what-are-clouds-grades-5-8/)
  and [cloud-radiation primer](https://science.nasa.gov/earth/earth-observatory/clouds-and-radiation/)
  are the scientific frame for these deliberately bounded visual approximations.
- Earth, clouds, atmosphere, and Moon use finite-angular-disc eclipse visibility, so Earth can
  shadow the Moon and the Moon can shadow Earth. The Moon uses measured albedo, gradient-derived
  bump normals, a Lommel–Seeliger/diffuse blend, restrained earthshine and opposition brightening,
  plus a slight artistic refracted-umbra tint. It has no measured geometric elevation.
- The Sun is a finite sphere with procedural photosphere granulation, spots, limb darkening, and
  the cheaper background-pass corona. This is a visual photosphere, not magnetohydrodynamics.

## Performance policy and honest limits

Framebuffer allocation is capped at 2,000,000 pixels and device-pixel ratio at 2. An adaptive
quality multiplier ranges from 0.75 to 1.0 on top of that static pixel budget. It reduces resolution
only after sustained slow animation-frame cadence and recovers in larger, cautious steps after
sustained stable cadence. The 0.75 floor retains more than half the native fragments instead of
stretching a half-resolution buffer into obvious pixel blocks. Long positive finite foreground
frames still contribute to the timing average and slow-frame decision, but each frame's evidence is
bounded so one stall cannot dominate the controller. These are safeguards, not a measured frame-rate
guarantee across browsers or GPUs.

Leaving an installation cancels its animation frame, removes its view-scoped browser listeners,
and deletes its WebGL buffers, vertex arrays, textures, and programs. Re-entering therefore creates
one fresh renderer instead of retaining every previously visited scene.

The synchronously compiled startup program is intentionally the bounded orbital shader described
above. A higher-cost generated near-surface shader remains in the repository and is compiled by
`make shader-check`, but it is not selected at runtime: synchronous compilation of that larger
program can stall a browser UI thread or trip a GPU watchdog. Splitting detailed work into safe
distance-specific programs is still future work.

Global texture resolution plus filtered procedural bands support orbital views, broad approaches,
and stylized close flyovers. Blue Marble is about 9.8 km per equatorial texel; the artistic terrain
field is about 19.6 km per equatorial texel with roughly 39.2 m vertical encoding increments.
Procedural material and bounded local displacement can add stable smaller-scale variation, but they
cannot reconstruct measured roads, rocks, coastlines, lakes, or local topography absent from the
sources. There is no measured tiled terrain LOD, lunar displacement, dynamic weather data,
physically simulated ocean, exact eclipse-contact solver, global multiple scattering, or shared HDR
exposure. The repository contains offline cube-sphere/elevation builders and renderer-independent
tile logic, but those tiles are not generated, shipped, fetched, or sampled by the browser renderer.

The physically plausible 1.5 km cloud base is only about 0.024% of Earth's radius. It is below one
pixel in ordinary whole-planet views, so separation from the ground is conveyed by volume shading
and displaced cloud shadows there; the clear-air gap becomes geometrically resolvable only during a
close or horizon view. Making the gap obvious from orbit would require intentionally exaggerating
altitude rather than improving physical scale. The browser's first **View Earth surface** preset
selects the most sun-facing of six authored, moderately cloudy land sites, places the camera 300 m
above the conservative terrain collision surface, and looks 18 degrees downward along the local
north tangent. Cloud base and local terrain vary, so this provides a repeatable below-cloud view
without claiming one fixed ground-to-cloud or camera-to-cloud distance.

Run `make shader-check` to compile the vertex, background, point-star, startup orbital, and generated
detailed shader sources with `glslangValidator`. `make check` includes this target along with Rust,
Python, browser-safety, and production-build checks.
